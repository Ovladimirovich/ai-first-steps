# AI Video Factory — план надстройки над существующим движком

**Статус:** план согласован пользователем. M0/M1 готовы; загрузка своего фона сцены, content-hash кэш сегментов MP4 и точечная пересборка реализованы. Для текста добавлены локальный llama.cpp (адрес `127.0.0.1:8081`) и GigaChat (cloud API); реальное подключение GigaChat требует локальных учётных данных, а llama.cpp — проверки на Windows-компьютере. Настоящий голос и генерация изображений сервисом ещё не подключены.
**Дата:** 03.11.2026 · ветка `arena/c0c3d897-ai-first-steps`

## 1. Коротко: что предлагаю

Оставляем конвейер `текст → озвучка → тайминги → кадры → рендер` **как есть** и превращаем его в движок.
Сверху ставим четыре вещи:

1. **Спецификация ролика** (`spec.json`) — единственный источник правды. Её читает и интерфейс, и пайплайн.
2. **Диспетчер этапов** — знает, что уже посчитано, что устарело и что можно переиспользовать.
3. **Провайдеры генерации** — текст, голос, картинки. Сейчас подключаются «демо»-заглушки, позже — реальные сервисы. Интерфейс не меняется.
4. **Пять экранов** — Замысел → Сценарий → Озвучка → Картинки → Рендер. Один экран = одна задача, дорогие операции только по кнопке «Подтверждаю», цена показывается до запуска.

Первым делом — сквозной прогон на заглушках: вы вводите тему, через несколько минут получаете настоящий MP4 в плеере. Никакой косметики до этого момента.

| Что | Факт из репозитория |
|---|---|
| Два готовых ролика | Оригинал 85 реплик / 695 с; Pixar «Зачем ИИ школьнику» 57 реплик / **379.0 с** / 25 сцен |

| Аудио | склейка `adelay`+`amix`+`loudnorm -16` в один трек, отдельные mp3 на реплику |
| Зависимости | Python + Pillow + numpy + imageio-ffmpeg. **Всё ставится из PyPI, ffmpeg приезжает колёсами** — проверено в песочнице |

**Проверил главное для плана:** правила тайминга воспроизводятся бит-в-бит. Я пересчитал `timing-pixar.json` по формулам `build_pixar_timing.py` — 57 реплик, **0 расхождений по времени старта, итог 379.0 с**. Значит правила можно переиспользовать как есть, не переизобретая.

### 2.1. Где движок жёстко привязан к одному ролику

Это не упрёк авторам — это «мастерская под один заказ». Для фабрики важно знать точный список:

| Место | Проблема | Что делаем |
|---|---|---|
| `TIMING`, `VOICE` в начале `build_ffmpeg_video.py` | пути зашиты на `timing-pixar.json` | добавить `--timing` и `--voice` (по умолчанию — сегодняшние пути) |
| `SCENE_TITLES` — словарь в коде | заголовки сцен нельзя задать извне | добавить `--scene-titles` (JSON), при отсутствии — прежний словарь |
| `card_w = 1400` в `draw_pixar_frame` | вёрстка рассчитана только на 1920×1080 | **рендерим только 1920×1080**; проверено: на 720p текст и аватар уезжают за край кадра (см. замер) |
| один `bg_path` на весь ролик | нет картинки на сцену | этап 3: `--scene-bg-dir` + кэш сегментов |

**Итого вмешательство в движок:** 3 необязательных параметра на первом этапе + 2 на третьем. Все с дефолтами = текущее поведение. Существующие команды, CI и документация не меняются. Если это неприемлемо — есть обходной путь (своя копия цикла кадров), но он дублирует логику пружины/караоке и почти гарантированно разъедется. Рекомендую флаги.

## 4. Единая спецификация ролика — контракт

### 4.1. Принцип

`spec.json` содержит **только то, что задаёт человек и что является замыслом**. В нём нет ни одной вычисленной величины: ни длительностей, ни путей к промежуточным файлам, ни статусов. Поэтому его можно править руками, показывать в интерфейсе целиком и сравнивать версии.

Всё производное (озвучка, тайминги, кадры, рендер) живёт в отдельном индексе артефактов и вычисляется из спеки.

### 4.2. Структура (v1)

```jsonc
{
  "spec_version": 1,

  "intent": {
    "theme": "Почему человек чихает и зачем это нужно",
    "audience": { "preset": "kids_11_14", "note": "урок биологии, 6 класс" },
    "target_duration_s": 60,
    "tone": "дружелюбно, с лёгким юмором, без сложных слов",
    "language": "ru"
  },

  "heroes": [
    { "id": "h1", "name": "Бит", "role": "explains",
      "about": "робот-кубик, добрый, любит аналогии",
      "look": "бирюзовый кубик с экраном-лицом",
      "voice": { "provider": "demo", "voice_id": "male-warm", "rate": 1.0 } },

    { "id": "h2", "name": "Маша", "role": "asks",
      "about": "школьница 12 лет, любопытная",
      "look": "худи, рюкзак",
      "voice": { "provider": "demo", "voice_id": "female-young", "rate": 1.0 } }
  ],

  "look": {
    "style_preset": "warm_workshop",          // warm_workshop | bright_clouds | night_space
    "palette": { "bg": "#FFF6E0", "ink": "#1B2A4A",
                 "accent": "#2EE6D6", "highlight": "#FFD23F" },
    "reference_image": null                    // картинка-настроение, если есть
  },

  "format": { "width": 1920, "height": 1080, "fps": 30, "captions": "burned" },

  "timing_policy": { "preset": "legacy_v1" },  // проверенные паузы движка

  "script": {
    "generator": { "provider": "demo", "version": "rule-v1" },
    "scenes": [
      {
        "id": "s1", "order": 1,
        "title": "Чихание — это защита",
        "purpose": "hook",                     // hook | point | check | payoff
        "goal": "зритель удивляется: чихание — не простуда, а защита",
        "visual_note": "вокруг летают пылинки, Бит в очках",
        "image": { "mode": "style", "path": null },   // style | upload | generated
        "lines": [
          { "id": "l1", "hero": "h2", "text": "Почему мы чихаем?", "pause_after_s": null },
          { "id": "l2", "hero": "h1",
            "text": "Это защита! В нос попадает пыль — и мозг даёт команду: выдохнуть резко.",
            "pause_after_s": null }
        ]
      }
    ]
  }
}
```

### 4.3. Правила контракта

| Правило | Зачем |
|---|---|
| `spec_version` — целое; при загрузке старой спеки выполняется миграция с резервной копией | спека будет расти, ролики не должны ломаться |
| Все ссылки по `id`, а не по индексу (`hero: "h1"`, `line.hero`) | перестановка сцен и реплик не рвёт связи |
| Текст реплики — единственный носитель смысла; заголовок сцены и `goal` нужны интерфейсу и проверке «одна идея — одна сцена» | человек правит текст, система проверяет смысл |
| `pause_after_s: null` = «по правилам движка» | паритет с готовыми роликами сохраняется; ручная пауза — по желанию |
| `image.mode` описывает **решение**, а не файл: `style` = взять из стиля, `upload` = своя картинка, `generated` = сгенерировать | правка в интерфейсе = правка в производстве |
| `target_duration_s` — цель, а не гарантия: реальная длительность появляется после озвучки | длительность ролика определяется речью, а не таймером |
| Нет полей `status`, `duration`, `cost` | их нельзя «забыть обновить»; они вычисляются |

### 4.4. Что лежит рядом (не часть контракта)

```
.factory/projects/<id>/
  spec.json            ← контракт
  project.json         ← id, заголовок, revision, где остановился человек
  artifacts/index.json ← производное: ключи кэша, что устарело
  audio/<line_id>.mp3  voice_track.mp3    timing.json  subtitles.srt
  frames/<scene_id>.jpg
  renders/draft.mp4  final.mp4
  logs/
```

## 5. «Повторная работа оплачивается один раз» — как это устроено

### 5.1. Ключ вместо флага «сделано»

У каждого артефакта есть ключ — отпечаток всего, от чего он зависит:

| Артефакт | Из чего складывается ключ |
|---|---|
| озвучка реплики | текст + голос героя + скорость + версия провайдера |
| таймлайн сцены | длительности её реплик + правила пауз |
| кадр сцены | заголовок + стиль/картинка + порядок сцены |
| сегмент видео сцены | кадр + таймлайн сцены + настройки рендера |

Артефакт считается готовым, если его ключ совпадает с сохранённым. Никаких «перерендерить на всякий случай».

### 5.2. Гранулярность экономии

| Что вы изменили | Пересоберётся |
|---|---|
| одну реплику | 1 mp3 + тайминги затронутых сцен + 1 кадр + 1 сегмент видео + склейка |
| заголовок сцены | 1 кадр + 1 сегмент |
| голос героя | mp3 всех его реплик + тайминги + затронутые сегменты |
| картинку сцены | 1 кадр + 1 сегмент |
| порядок сцен | сегменты переставляются, звук переклеивается; **ни одной генерации голоса или картинки** |
| стиль целиком | кадры всех сцен, озвучка не трогается |

Формула, которую увидит человек: «Пересоберутся 3 из 25 сцен · озвучка: 0 из 57 реплик · ≈40 секунд».

### 5.3. Как это выглядит на экране

Никаких хешей и ключей на экране. Вместо них — значки на шагах:

**✓ подходит · ◐ идёт работа · ○ ещё не начинали · ⟳ устарело · ⚠ нужна правка**

Если после рендера вы поправили текст сцены 3, шаг «Рендер» получает **⟳**, а на его экране появляется строка: «Ролик устарел: изменена реплика в сцене 3. Пересобрать только её — ≈15 секунд». Ничего не пересобирается само и ничего не теряется молча.

## 6. Пять шагов: что на каждом экране

Общая рамка: сверху полоса из пяти шагов (текущий подсвечен, значки статуса, любой шаг можно открыть), справа — мини-плеер «что получится». Технические слова на экран не попадают: «сценарий», «озвучка», «кадры», «ролик», «стоимость», «черновик/финал».

### Шаг 1 — Замысел
Полей ровно столько, сколько смысла:
- тема (свободный текст, 1–3 предложения);
- для кого (3 пресета + уточнение словами);
- длительность (30 / 45 / 60 / 90 / 120 с, по умолчанию 60);
- герои (карточки: имя, роль «объясняет/спрашивает», характер);
- как выглядит (3 стиля с превью-картинкой);
- какой голос (у каждого героя — выбор из пресетов, темп).

Сразу под полями — **дешёвый прогноз без единого обращения к ИИ**: «Получится ≈6 реплик ≈55 секунд ≈380 знаков». Если тема слишком широкая для 60 секунд, честно предупреждаем до генерации, а не после.

Кнопка: **«Написать сценарий»** (дешёвая операция, подтверждения не требует, цена всё равно показана).

### Шаг 2 — Сценарий
- Сверху: цель vs прогноз («57 секунд из 60 — хорошо»), проверки: одна идея на сцену, нет перегруза терминами, есть крючок и финал.
- Сцены — карточками: заголовок, «зачем эта сцена», реплики с пометкой говорящего; текст правится на месте, реплику можно убрать, добавить, переставить.
- Одна сцена переписывается отдельно («другой вариант»), весь сценарий — тоже.
- Каждая правка тут же показывает последствия: «обесценится озвучка 1 реплики и кадр сцены 3».
- Скачать сценарий текстом.

Кнопка: **«Озвучить 6 реплик · ≈380 знаков · ≈25 с · $0.05»** → экран подтверждения (шаг 3).

### Шаг 3 — Озвучка
- До запуска: смета (реплик, знаков, секунд, цена) и кнопка **«Подтверждаю»**. Сервер не начнёт работу без подтверждения, привязанного к текущей версии сценария: если текст изменился между сметой и запуском — работа не стартует, смета пересчитывается.
- После: каждая реплика — плеер, реальная длительность, «переозвучить только эту». Уже озвученные реплики при повторном запуске не оплачиваются: показываем «оплачено ранее: 5 из 6».
- Итог: реальная длительность ролика, файл субтитров.

### Шаг 4 — Картинки
- Показываем **ровно тот кадр, который попадёт в ролик** (тот же код отрисовки движка), а не абстрактный эскиз.
- У каждой сцены режим: «из стиля» / «своя картинка» (загрузка) / «сгенерировать» (этап 3 плана).
- На первом прогоне честно пишем: «Демо-режим: картинки берутся из выбранного стиля. Генерация картинок — следующим этапом».
- Пакетная генерация — со сметой до запуска.

### Шаг 5 — Рендер
- Чек-лист: что готово, что устарело, что будет сделано.
- Две кнопки с честными оценками: **«Черновик ≈40 с»** (быстрая сборка без анимации) и **«Финал ≈3 мин»** (с пружиной, караоке, музыкой). Обе — после подтверждения.
- Прогресс: процент, этап, сколько осталось, живая строка журнала понятным языком.
- Результат: видео прямо на экране, размер и длительность, «Скачать MP4», «Открыть папку», «Пересобрать» (с явным ответом, что именно пересоберётся).

## 7. Честность заглушек

Первый прогон делается без внешних сервисов. Чтобы это не выглядело обманом, на экране всегда виден бейдж режима:

| Что | Демо-режим (сейчас) | С ключами (этап 2) |
|---|---|---|
| Сценарий | шаблонный генератор по теме и структуре | LLM по JSON-схеме + валидатор + один проход починки |
| Голос | тишина с **реальной оценкой длительности** по тексту (mp3 создаётся ffmpeg) | TTS-сервис; длительности — `ffprobe` как сейчас |
| Картинки | фон выбранного стиля + карточка сцены | TTS→генерация изображений, своя картинка на сцену |
| Рендер | **настоящий** MP4 через существующий движок | тот же движок |

Ключевое: в демо-режиме **озвучка — заглушка, но файлы и тайминги настоящие**. То есть проверяется ровно тот путь, который потом поедет с живым голосом: `ffprobe` → `timing.json` → сборка. Подмена одного звена не потребует переделки остальных.

Бейдж: «демо-генераторы · рендер настоящий» — кликабельный, с объяснением одним абзацем.

## 8. Сквозной прогон (то, что я сделаю сразу после согласия)

**Сценарий приёмки, 8 шагов, ~4 минуты:**

1. `python -m factory` → открывается русский интерфейс.
2. Ввести тему «Почему мы чихаем?», 60 секунд, 2 героя, стиль «тёплая мастерская».
3. Шаг 2: появился сценарий (≈6 реплик, 3 сцены), правится текст.
4. Шаг 3: смета → подтверждение → 6 заглушек-реплик с реальными длительностями.
5. Шаг 4: 3 кадра-раскадровки из того же кода, что рисует движок.
6. Шаг 5: «Черновик» → подтверждение → готовый MP4 играет в браузере.
7. Поправить одну реплику → система показывает «⟳ 1 озвучка, 1 кадр, 1 сцена ролика» → «Пересобрать» пересобирает только это.
8. Проверить, что старые команды движка работают как раньше.

**Чем докажу, что движок не сломан:**

- **Тест паритета тайминга:** пересчёт `timing-pixar.json` по правилам движка даёт те же 57 реплик, 0 расхождений, итог 379.0 с — уже проверено, станет автотестом.
- **Тест паритета кадра:** кадр, нарисованный фабрикой, совпадает с кадром движка байт-в-байт при тех же входах (сравнение хеша изображения).

## 11. Инженерное приложение

### 11.1. Стек и запуск
- Python 3.10+, только stdlib + то, что уже требует движок (Pillow, numpy, imageio-ffmpeg). Никаких `npm`, никакой сборки.
- HTTP-сервер на `http.server` + `ThreadingHTTPServer`, порт 7860, привязка `0.0.0.0` (нужно для предпросмотра в песочнице).
- Одна фоновая нить-очередь на тяжёлые задачи: два рендера одновременно на 2 ядрах — плохая идея. Прогресс — опрос статуса раз в секунду.
- Данные — `.factory/` в корне репозитория (в `.gitignore`). Готовые MP4 туда же; если захотите показать ролик в git — по образцу `preview/`.

### 11.2. API (внутренний, для интерфейса)

| Метод | Назначение |
|---|---|
| `GET /api/settings` · `PATCH /api/settings` · `POST /api/settings/test` | режим демо/локальный llama.cpp и проверка локального соединения |
| `GET /api/projects` · `POST /api/projects` | список / создание ролика |
| `GET/PATCH /api/projects/{id}` | чтение и правка спеки (PATCH проверяет `revision` — защита от двух вкладок) |
| `POST .../script/draft` · `POST .../script/scene/{sid}/redraft` | черновик сценария (дёшево) |
| `POST .../voice/plan` → `{plan_id, cost, duration_s, units}` | **смета без побочных эффектов** |
| `POST .../voice/run {plan_id}` | запуск; сервер сверяет план с текущей версией спеки, иначе 409 «сценарий изменился» |
| `POST .../frames/plan` · `.../frames/run` · `.../frames/upload` | картинки сцен |
| `POST .../render/plan` · `.../render/run {plan_id, kind: draft\|final}` · `GET .../render/status` · `POST .../render/cancel` | рендер |
| `GET .../artifacts` | что свежо, что устарело и почему (для значков) |
| `GET /media/...` | mp3, кадры, mp4 |

Принцип «дорогое только по подтверждению» реализован на сервере, а не в интерфейсе: без `plan_id` от текущей версии спеки дорогая операция физически не запускается. Ошибка в вёрстке не может стоить денег.

### 11.3. Провайдеры
Для сценария доступны `demo`, локальный `llama_cpp` и облачный `gigachat`. llama.cpp обращается только к loopback-адресу `http://127.0.0.1:8081/v1` (настраивается); GigaChat получает OAuth-токен из секретов локального `.env`, TLS-проверка включена. Запросы текста сериализуются. Перед отправкой в облако интерфейс предупреждает о передаче текста и требует согласия. Для голоса остаётся тихая демо-дорожка; картинки — выбранный стиль или собственная загрузка.

```python
class TextProvider:    def draft(spec) -> Script;  def redraft_scene(spec, scene_id) -> Scene
class VoiceProvider:   def synth(text, voice, rate) -> bytes(mp3)
class ImageProvider:   def render(prompt, look) -> bytes(jpg)
```
Плюс обязательные метаданные: `name`, `version`, `price_per_unit` (для смет), `estimate_s(units)` (для «сколько ждать»). Смета и «оплачено ранее» считаются из них — новые сервисы подключаются без правки интерфейса.

### 11.4. Тайминг — один модуль
`pipeline/timing.py` реализует ровно правила движка (1.1 с между сценами, 0.42/0.55 с после реплики, 4.2 с на «чек-вопрос», ≤84 знака на субтитр) и покрыт тестом паритета. Легаси-скрипты **не переписываю**; фабрика их не импортирует, чтобы случайно не сломать, а воспроизводит правила в одном месте и сверяет результат с эталоном.

### 11.5. Оценки, которые интерфейс показывает до запуска

| Величина | Формула | Откуда число |
|---|---|---|
| длительность озвучки | знаки ÷ 10.8 симв/с | замер по реальной дорожке Pixar (3435 знаков / 317.9 с речи) |
| длительность ролика | озвучка + паузы по правилам | тот же модуль, что строит таймлайн |
| время рендера | кадры × стоимость кадра | замер в этой песочнице: 0.04 с/кадр при 720p, 1080p дороже |
| деньги | знаки × цена/1000 + картинки × цена | прайс провайдера из настроек |

Константа «символов в секунду» калибруется автоматически после первого реального прогона озвучки — прогноз со временем становится точнее без правки кода.

### 11.6. Тесты
- паритет тайминга с `timing-pixar.json` (эталон в фикстурах);
- паритет кадра с движком (хеш картинки);
- регрессия движка: `--only 3` до и после правок;
- кэш: правка одной реплики → ровно 1 новая озвучка, 1 кадр, 1 сегмент (по индексу артефактов);
- гейт: `run` без `plan_id` → 409, после правки спеки старый `plan_id` → 409.

## 12. Риски

| Риск | Как проявляется | Что делаю |
|---|---|---|
| Движок заточен под один ролик | нельзя передать свой тайминг, голос, заголовки | 3 необязательных флага + тест регрессии |
| Вёрстка рассчитана на 1920 | на 720p текст уезжает за кадр (проверено замером) | рендерим 1080p, «черновик» — тот же размер, но быстрый пресет |
| 2 ядра в песочнице | «Финал» 60-секундного ролика ≈3 мин | «Черновик» первым, «Финал» по кнопке; одна задача за раз |
| Нет ключей генерации | живой голос/картинки не проверить здесь | честный демо-режим; адаптеры пишутся по документированным API и включаются вашим ключом. Прогон с ними вы делаете у себя — я дам чек-лист на 5 минут |
| Стоимость растёт незаметно | пакетные операции | смета до запуска + серверный гейт |
| Дублирование логики таймингов | ролик «съезжает» | один модуль + тест паритета 379.0 с |
| Долгий «немой» демо-ролик | выглядит сломанным | предупреждение на шаге 3 + быстрый способ вставить свой mp3 на реплику |
