# Общий протокол разработки и локальной проверки

## Общая схема

**Arena → GitHub → локальный инженер → локальный отчёт → Arena**

Этот документ описывает взаимодействие ролей; задачи и технический статус остаются в [ROADMAP.md](ROADMAP.md). Он не дублирует продуктовый план.

## Распределение ответственности

### Arena — основной разработчик

- Реализует продуктовые задачи и общую архитектуру.
- Запускает доступные автоматические тесты.
- Коммитит и публикует изменения в закреплённую ветку GitHub.
- Обновляет ROADMAP, PROGRESS и инструкции по фактическому состоянию.
- Чётко перечисляет, что требует локальной проверки.

### Локальный инженер — независимый проверяющий

- Безопасно синхронизирует закреплённую ветку с Windows-компьютером.
- Проверяет локальный запуск, Piper/ComfyUI/GPU и итоговый MP4, если это относится к задаче.
- Фиксирует результаты в `docs/factory/LOCAL_VALIDATION.md`.
- Передаёт воспроизводимые ошибки инженеру Arena.
- Не ведёт параллельную разработку; кодовые исправления делает только по отдельному согласованию.
- Не отправляет изменения в GitHub без отдельного разрешения владельца.

### Владелец проекта

- Принимает продуктовые и архитектурные решения, когда они действительно требуются.
- Даёт отдельное согласие на облачные/платные действия и на push локального инженера.
- Оценивает субъективное качество (например, разборчивость речи или пригодность кадра); не обязан интерпретировать технические логи.

## Передача задачи

1. Arena завершает согласованную работу, публикует коммит и указывает его hash, тесты и локальные проверки.
2. Локальный инженер сверяет состояние репозитория и безопасно получает этот коммит. Неотслеживаемые локальные файлы и `.factory` сохраняются.
3. Локальный инженер выполняет только назначенные проверки в реальной среде.
4. Результаты добавляются отдельной датированной записью в `LOCAL_VALIDATION.md`.
5. Чтобы результат стал доступен Arena, владелец либо разрешает отправить только отчёт в общую ветку, либо передаёт его безопасный текстовый блок. Без разрешения push не выполняется.
6. Arena читает отчёт, исправляет дефекты в своей роли основного разработчика и при необходимости назначает повторную локальную проверку.

## Git и защита данных

- Общая точка синхронизации — закреплённая ветка GitHub; одновременно работает только один автор изменений.
- Не использовать `git reset --hard`, `git clean`, force-push и массовую очистку.
- Не применять `git add -A` при наличии локальных неотслеживаемых файлов; добавлять только проверенные файлы задачи.
- `.factory`, `.env`, модели, локальные аудио/видео, готовые проекты и временные логи не публикуются.
- При грязном рабочем дереве, неожиданном tracked diff или расхождении истории — остановиться, сохранить данные и сообщить владельцу.
- Никаких скрытых облачных вызовов: перед облачной генерацией должны быть явное согласие, раскрытие передаваемых данных и лимит расходов.

## Статусы завершения

Статусы не взаимозаменяемы:

- **IMPLEMENTED** — функциональность реализована в коде.
- **AUTOMATED-VERIFIED** — автоматические проверки пройдены.
- **LOCALLY-VERIFIED** — локальный инженер подтвердил работу в реальной среде.
- **ACCEPTED** — владелец принял пользовательский результат.

Главное правило: один проект, один основной разработчик, один независимый локальный проверяющий и ясная запись о том, что именно уже доказано.
